# Story 5.5 — Panneau de chat (V1.1)

Cadrage : `docs/v1.1-chat-slm.md`. Contrat : `docs/specs/5.1-outils-chat.md`, `5.6-client-slm.md`. Édition `roue-chat.html` seulement : `roue.html` ne contient aucun code du chat (`check:size`).

## Critères d'acceptation
- C1. Une seule cascade, créée une fois (`creerCascade`) dans `src/main-chat.ts`. Les réglages modifient en place l'objet `options` lu par les étages ; la cascade n'est jamais reconstruite.
- C2. Chaîne sans raccourci (`src/chat/controleur.ts`, sans DOM) : `cascade.decider` puis `planifier(decision, etatDomaine)` puis, selon le plan : `clarifier` (candidats en boutons, doublons fusionnés), `refuser` (message de `textes.ts`, ceux de l'interface pour rotation, moins de 2 noms, cadeaux épuisés), `etapes` (carte « Confirmer / Annuler » avec récapitulatif si `confirmation`, sinon `executerPlan`). Aucune écriture dans l'état hors `Actions`.
- C3. Clarification : le candidat choisi remplace la première valeur texte de la décision qui donne un plan sans nouvelle clarification. Homonymes strictement identiques : un nom ne les distingue pas, message « renommez-en une, ou demandez « supprime les deux » ». Clarification venue d'un étage (sans paramètre) : la commande est reprise avec le nom ajouté.
- C4. `EtatChat` reconstruit à chaque commande : `noms`, `cadeaux`, `rotation` (roue), `prochainCadeau = cadeaux[attribues]`, `historique` (3 derniers échanges).
- C5. Une commande à la fois : saisie désactivée pendant la décision ; un `AbortController` annule la commande en cours si une autre est envoyée ou si le panneau se replie ; une décision tardive est ignorée.
- C6. Avis `indisponible` : un seul, hors du fil, quand un étage `slm` ou `decision` (garde de type sur `etat()`) l'est ; il donne `OLLAMA_ORIGINS=http://localhost:5200`. Sans modèle, aucun avis.
- C7. Réglages (modèle SLM, modèle de décision) en `localStorage` (`reglages-chat.ts`, try/catch), vides par défaut ; vides, les étages 2 et 3 restent inactifs. `OptionsEtages.modeleDecision` est ajouté pour l'étage de la 5.10.
- C8. Accessibilité : fil en `role="log"` `aria-live="polite"` ; focus rendu à la saisie (ou au premier bouton d'une attente, « Annuler » pour une confirmation) ; Échap replie ; cibles de 44 px, jetons de `page.css`.
- C9. Tout texte en `textContent` (commande, noms, réponse, texte d'un modèle) ; aucun lien fabriqué.
- C10. Mise en page : écran large (>= 52 rem), le panneau ouvert est en tête de la colonne du panneau, la roue reste collante ; écran étroit, tiroir fixé en bas, replié par défaut, plafonné à 45 % de la hauteur, avec une marge basse sur la page ; pas de défilement horizontal.
- `main.ts` exporte `application` (`actions`, `roue`, `root`), seul point de branchement de l'édition chat.

## Vérification
`controleur.test.ts` (20 cas : sans confirmation, confirmée, refusée, clarifier, homonymes, rotation, moins de 2 noms, nom hostile, annulation par une nouvelle commande, fermeture, état construit, avis unique), `reglages-chat.test.ts`. E2E `tests/e2e/chat-panneau.spec.ts` : panneau, réglages, 320 et 1920 px actifs ; les parcours à commandes simples (ajout, homonyme, suppression confirmée, rotation, nom hostile) sont `fixme` tant que l'étage règles (5.3, PR #31) n'est pas dans `main`.
