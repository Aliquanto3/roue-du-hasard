# Story 6.3 — Prénoms à l'oral (V1.3)

Cadrage : `docs/v1.1-chat-slm.md` (section voix, « le point dur : les prénoms »). S'appuie sur 6.1 (indice `prompt` du STT, mesures) et 6.2 (client `src/chat/stt.ts`, bouton, relais `/stt`). Code dans `src/chat/` seulement.

## Critères d'acceptation
- C1. Indices : le `prompt` envoyé au STT contient les prénoms de la roue (déjà fait par 6.2, `construireIndice`) ; vérifier l'ordre (les plus récents ou la liste entière dans la borne de 200 caractères) et le documenter.
- C2. Rapprochement : sur une commande issue de la voix, chaque mot ou groupe de mots qui ressemble à un prénom connu est rapproché par la clé phonétique et la proximité de `regles.ts` (réutilisées, pas dupliquées : exporter ce qu'il faut). Le résultat est un score par correction (exact = 1 ; phonétique ; proche).
- C3. Seuil : sous un score seuil (constante nommée, réglée sur le lot `dev`), la correction n'est pas appliquée en silence : la commande corrigée est montrée avec la demande de confirmation (« Vous vouliez dire Thibault ? »), par le même mécanisme de confirmation que `planifier`. Au-dessus, la correction est appliquée et affichée.
- C4. Nouveau nom dicté (`ajouter`, `renommer` vers un nom absent de la liste) : toujours montré pour correction avant exécution, jamais ajouté en silence, puisque le STT écorche les prénoms inconnus.
- C5. Inspection (5.7) : pour une commande vocale, transcription brute, corrections (avant, après, score, méthode), latence STT ; le verdict distingue une erreur d'écoute (transcription fausse) d'une erreur de décision (cascade fausse sur une transcription juste).
- C6. Aucune règle écrite d'après `test` ni `test2` (garde-fou `src/banc/fuite.test.ts`).

## Tests
- Unitaires sur les lignes de catégorie « transcription orale » du lot `dev` (`docs/v1.1/corpus-commandes.jsonl`) : chaque ligne passe par le rapprochement puis la cascade ; scores et seuil testés ; cas Thibaut/Thibault, Gaëtan, Anaël, homonymes, nom composé (« Marie-Claire » ne devient pas « Marie »), nom nouveau.
- Banc : `npm run banc:chat -- --moteur regles` inchangé ou meilleur sur `dev`.
- E2E : un cas dans `tests/e2e/chat-voix.spec.ts` (STT simulé renvoyant « supprime Thibaut » pour une roue avec Thibault) : confirmation affichée puis exécution.

- Essai en salle et enregistrements : 6.4 (Anaël).

## Réalisation
- `src/chat/oral.ts` : `rapprocher(commande, noms, seuil)` découpe la commande en mots (ponctuation de bord gardée) et rapproche chaque mot, ou groupe de deux à trois mots, d'un prénom de la liste. Réutilise `cle`, `cleFrancaise` et `distance` de `regles.ts` (exportées, rien de dupliqué). Scores : exact 1 ; phonétique stricte 0,9 ; phonétique souple 0,75 ; proche (distance de 1 ou 2) de 0,6 à 0,8 selon la distance (Thibaut/Thibault : 0,775). Deux prénoms différents au même rang : aucune correction, la cascade demande lequel. Un groupe de mots n'est rapproché que d'un nom composé de même écriture (« Marie Claire » devient « Marie-Claire ») ; « Marie-Claire » ne devient jamais « Marie ». Mots de commande et mots-outils écartés (liste courte dans `oral.ts`).
- Seuil `SEUIL_CORRECTION` = 0,85, réglé sur le lot `dev` (transcription orale) : « mari » et « pol » (clé stricte, 0,9) doivent passer sans question, comme l'attend le lot (`confirmation: false`) ; les variantes d'écriture (Thibaut, 0,775) et le phonétique souple (0,75) restent toujours confirmés, car deux prénoms réels peuvent s'en approcher (Anne et Hanne).
- C3 : dans `controleur.ts`, la commande corrigée part dans la cascade, puis `planifier`. Sous le seuil, une confirmation est forcée (même carte et même `confirmer` que `planifier`) avec « Vous vouliez dire … ? » ; au-dessus, la correction est appliquée et affichée (« J'ai compris : … »).
- C4 : pour une commande dictée, `ajouter`, `coller` et `renommer` vers un nom absent de la liste demandent toujours confirmation. Ce qui suit « ajoute » et « renomme X en » n'est pas rapproché (un nom nouveau ressemble souvent à un existant sans l'être). Une commande tapée n'est pas concernée.
- C1 : `construireIndice` garde l'ordre de la liste ; un prénom qui ne tient pas dans les 200 caractères est omis, les suivants restent. Aucun changement (déjà couvert par `stt.test.ts`).
- C5 : `transcription` de l'entrée d'inspection gagne `corrections` (avant, après, score, méthode, appliquée) et `corrigee`, validés au chargement et affichés dans le détail. Le verdict « erreur d'écoute » ou « erreur de décision » existait déjà (case « Erreur d'écoute », 5.7) : une entrée vocale montre la transcription brute et les corrections, de quoi juger l'écoute avant la décision.
- C6 : `regles.ts` ne gagne aucun mot, seulement deux exports ; `fuite.test.ts` vert.
- Tests : `oral.test.ts` (rapprochement, lot `dev` transcription orale), `controleur.test.ts`, `inspection.test.ts`, `regles.test.ts`, E2E `chat-voix.spec.ts` (« supprime Thibaut » pour une roue avec Thibault ; le cas « Zoé Martin » dicté passe maintenant par la confirmation de nom nouveau).
- Banc `regles` sur `dev` : 100/100, inchangé (le rapprochement ne touche pas les commandes tapées). `roue-chat.html` : 165 848 octets.

## Revue (second avis, passe 1)
- Haut : les verbes d'ajout, de collage et de renommage viennent maintenant de `regles.ts` (`V_AJOUTER`, `V_COLLER`, `V_RENOMMER` exportés ; « intègre », « add », « change le nom de »). Le contrôle des noms nouveaux (C4) juge le nom tel qu'entendu : un nom que le rapprochement aurait ramené à un nom existant reste nouveau, donc confirmé.
- Moyen, décision à valider par Anaël : sur une action destructive (supprimer, renommer, effacer l'historique, réinitialiser les couleurs, retirer les gagnants, annuler le dernier tirage), toute correction orale non exacte est confirmée, quel que soit son score (`correctionsAConfirmer`). Les autres actions gardent le seuil de 0,85. Conséquence : la ligne `ora-01` du lot `dev` passe à `confirmation: true` (« retire euh mari »), et le banc et `outils.test.ts` ajoutent cette règle pour la catégorie `transcription_orale`. Banc `regles` sur `dev` : 100/100.
- Bas : verbes écartés dérivés des `V_*` de `regles.ts` (plus de liste de verbes copiée) ; `meilleur` réutilise les paliers de `resoudreNom` (`paliersNoms`, partagé).
