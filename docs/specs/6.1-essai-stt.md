# Story 6.1 — Essai du micro et de la transcription (V1.3, mixte)

Cadrage : `docs/v1.1-chat-slm.md` (section voix). Story de mesure : elle choisit le moteur STT local et fixe le contrat que 6.2 consomme. Aucun code dans `roue.html` ; rien dans `src/main.ts`. Seul ajout au dépôt : `scripts/serveur-stt.mjs` (`npm run stt`), outil de poste hors livraison.

## Critères d'acceptation
- C1. Micro : dans Chrome, sur l'édition chat servie par `npm run chat` (`http://localhost:5200`, contexte sûr), `getUserMedia({audio:true})` fonctionne et `MediaRecorder` produit un enregistrement. Format retenu (WAV 16 kHz mono PCM, ou conversion côté page) noté pour 6.2.
- C2. Web Speech : constater, par source publique (documentation Chrome), que `SpeechRecognition` de Chrome passe par un service distant ; il est donc exclu (promesse : rien ne sort du poste).
- C3. Candidats, téléchargés hors dépôt (`%USERPROFILE%\tools\…`) : whisper.cpp (`whisper-server`, build CUDA Windows), modèles `small` et `large-v3-turbo` (quantifiés si besoin) ; Parakeet TDT 0.6B v3 via sherpa-onnx. Pour chacun : commande, port, point d'accès, requête et réponse, CORS.
- C4. Mesures sur ce poste (RTX 3060 Laptop 6 Go), jamais supposées : mémoire GPU (`nvidia-smi`), latence, justesse sur dix phrases françaises, prénoms compris.
- C5. Choix documenté ici : moteur, modèle, port, commande, budget mémoire sur 6 Go, `npm run stt`.

## Résultats

### C1. Micro et enregistrement (vérifié par Playwright Chromium, faux périphérique)
Script jetable `.banc/essai-micro.mjs` (non commité), Chromium lancé avec `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`, permission `microphone` accordée, page `http://localhost:5200/` servie par `npm run chat` :
- `window.isSecureContext === true`, origine `http://localhost:5200` ; `getUserMedia({audio:true})` renvoie une piste.
- `MediaRecorder` produit `audio/webm;codecs=opus` (24 558 octets pour 2 s). Pris en charge : webm/opus et webm, mp4 ; **pas** `audio/wav` ni ogg. Le WAV ne peut donc pas sortir directement du `MediaRecorder`.
- Conversion côté page, vérifiée : `AudioContext.decodeAudioData` (48 kHz) puis `OfflineAudioContext(1, n, 16000)` donne un PCM float 16 kHz mono ; en-tête WAV écrit à la main (44 octets) : 1,98 s, 63 404 octets, accepté tel quel par `whisper-server`. **Format retenu pour 6.2 : enregistrer en webm/opus, convertir dans la page en WAV 16 kHz mono PCM 16 bits, envoyer ce WAV.** (`whisper-server` n'accepte pas le webm sans `--convert` et ffmpeg, qu'on n'impose pas.)
- **CSP à élargir par 6.2** : `CSP_CHAT` (`vite.csp.ts`) n'autorise que `http://localhost:11434 http://127.0.0.1:11434` en `connect-src`. Constaté : le `fetch` vers `http://localhost:5201` depuis la page de chat échoue (`Failed to fetch`). 6.2 ajoute `http://localhost:5201 http://127.0.0.1:5201` (jamais dans `roue.html`). `getUserMedia` n'est pas régi par la CSP.
- **Reste pour la recette d'Anaël (6.4)** : micro réel (autorisation de la fenêtre Chrome, bon périphérique, niveau sonore) ; le faux périphérique émet un bip, pas de parole. Les permissions du profil Chrome d'Anaël pour `http://localhost:5200` ne sont pas vérifiables sans lui.

### C2. Web Speech
Source Chrome officielle non retrouvée : les pages developer.chrome.com consultées (`blog/voice-driven-web-apps-introduction-to-the-web-speech-api`, `docs/web-platform/on-device-speech-recognition`) sont rendues par script et leur texte n'a pas pu être lu ici ; à ajouter à la relecture si besoin. Source publique lue : MDN (`developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition`, consulté le 2026-11-04) : « On some browsers, like Chrome, using Speech Recognition on a web page involves a server-based recognition engine. Your audio is sent to a web service for recognition processing, so it won't work offline. » `processLocally` existe mais dépend d'un paquet de langue installé par le navigateur et n'est pas garanti ; pas de contrôle des prénoms. **Exclu.**

### C4. Mesures (poste : RTX 3060 Laptop 6 Go, 4 threads CPU)
Corpus : 10 phrases françaises de commande (prénoms Joséphine, Gaëtan, Thibault, Océane, Élodie, Kévin, Sébastien, Anaël, Léa, Mathieu, Clémence), voix française Microsoft Hortense (System.Speech), WAV 16 kHz mono, dans `.banc/stt/` (non commité). Durée des phrases : 1,7 à 3,1 s. Justesse : taux d'erreur de mots (WER) sans accents ni casse ni ponctuation. Latence : médiane de 110 requêtes chaudes (HTTP en local, `curl`/`fetch`, du POST à la réponse). Voix de synthèse : plus propre qu'une voix en salle, donc **borne haute de la justesse** ; la mesure réelle est la 6.4.

| Moteur | GPU seul | Latence chaude (médiane / max) | WER sans indice | Phrases exactes sans indice | WER avec `prompt` | Phrases exactes avec indice |
|---|---|---|---|---|---|---|
| whisper `small` (ggml-small, fp16, 488 Mo) | 791 à 831 Mo | 87 / 146 ms | 20,9 % | 6/10 | 4,7 % | 8/10 |
| whisper `large-v3-turbo` q5_0 (574 Mo) | 881 à 919 Mo | 165 / 202 ms | 7,0 % | 7/10 | **2,3 %** | **9/10** |
| Parakeet TDT 0.6B v3 int8 (CPU) | 0 (repli CPU) | 223 / 264 ms | 14,0 % | 6/10 | sans objet | sans objet |

**Cas réel = « avec indice ».** En usage, 6.2 envoie dans `prompt` les prénoms de la roue ; la colonne « avec indice » est donc la représentative, mais l'indice de l'essai contient les prénoms des phrases testées, ce qui est le cas favorable (roue contenant ces prénoms). « Sans indice » est le pire cas (prénom absent de la liste).
- Prénoms des 10 phrases : Joséphine, Gaëtan, Thibault, Océane, Élodie, Kévin, Sébastien, Anaël, Léa, Mathieu, Clémence.
- Prompt exact utilisé : `Commandes de la roue du hasard : ajoute, retire, supprime, remplace, vide la roue, fais tourner. Prénoms : Anaël, Léa, Mathieu, Joséphine, Océane, Gaëtan, Thibault, Élodie, Kévin, Sébastien, Clémence.`

Détail : Avec `large-v3-turbo`, il corrige Gaëtan, Anaël ; reste « Thibaut » pour Thibault (variante orthographique, à rattraper par 6.3). Sans indice, `small` entend « Supprime Élodie » comme « Suprime et l'audit ». Première requête après lancement : 270 à 350 ms.

**Mémoire GPU combinée** (`nvidia-smi --query-gpu=memory.used`, 6 144 Mo au total, 0 Mo au repos, `num_ctx` 4096 pour les modèles de chat ; `tev1` charge à 8192 par défaut) :

Avec Nemotron-Bolt, le SLM et le STT tiennent (5,3 Go) mais pas l'étage de décision en plus ; sans ajustement (`OLLAMA_MAX_LOADED_MODELS`, `num_ctx` réduit, `num_gpu` plafonné pour Bolt), la décision `tev1` serait rechargée à chaque alternance. Ce point est à trancher avant 6.2 si Bolt reste le SLM. Les totaux 3 567 et 5 334 Mo sont des relevés, pas des sommes.

## Choix (C5)
**whisper.cpp `whisper-server`, modèle `ggml-large-v3-turbo-q5_0.bin`, port 5201, 127.0.0.1.**
- Meilleure justesse (2,3 % avec indice, 9/10 exactes), seul moteur où l'on peut donner les prénoms de la roue en indice (`prompt`), le point dur du cadrage ; HTTP simple, appelable par `fetch` ; CUDA fonctionnel sans installation supplémentaire ; 0,9 Go de GPU, 165 ms pour une commande de 2 à 3 s.
- Écartés : `small` (3 fois plus d'erreurs sans indice, gain de latence sans intérêt à 165 ms) ; Parakeet (moins juste, pas d'indice, WebSocket binaire, GPU inutilisable sans cuDNN).
- Repli si le GPU manque : `whisper-server` en CPU n'a pas été mesuré ici ; hors périmètre.

### Contrat HTTP pour 6.2
- `POST http://localhost:5201/inference`, corps `multipart/form-data` : `file` (WAV 16 kHz mono PCM 16 bits), `language=fr`, `response_format=json`, `temperature=0`, `prompt` (phrase de commandes + prénoms de la liste, facultatif).
- Réponse 200 `{"text":" … \n"}` : à nettoyer (espaces, point final). Erreur d'entrée : 400. Pas d'authentification.
- CORS : `Access-Control-Allow-Origin: *` (en-têtes par défaut de `server.cpp`, sans option pour les changer).
- **Note de sécurité.** `whisper-server` répond en CORS `*` et ne contrôle pas le Host : une page tierce, y compris par DNS rebinding, peut lui envoyer de l'audio et lire la transcription, et utiliser le GPU. Elle ne lit pas le micro. Routes exposées par b5454 (lues dans `examples/server/server.cpp`, `--help` ne les liste pas) : `GET /` (page d'essai), `POST /inference` (chemin réglable par `--inference-path`), `OPTIONS /inference`, `POST /load` (**recharge un autre modèle par chemin : à fermer**), `GET /health`. Aucune option d'origine, de Host ni de clé d'API ; `--public` sert seulement des fichiers statiques.
- **Report à 6.2** : passer par un proxy `/stt` dans `scripts/serveur-chat.mjs` (qui contrôle déjà Host et origine), n'exposer que `POST /inference` vers `127.0.0.1:5201`, refuser `/load`, et ne pas ouvrir le port 5201 à la page directement (la CSP resterait alors sur `localhost:5200`). Non fait ici : le fonctionnement direct est vérifié.
- CSP de l'édition chat à élargir (voir C1).

### Lancement
```
npm run stt
```
`scripts/serveur-stt.mjs` lance `whisper-server` sur `127.0.0.1:5201` (`-l fr -t 4`). Chemins par défaut `~/tools/whisper-cpp/Release/whisper-server.exe` et `~/tools/whisper-modeles/ggml-large-v3-turbo-q5_0.bin`, surchargés par `WHISPER_SERVER` et `WHISPER_MODEL`. Aucune dépendance d'exécution ajoutée à `roue.html` ni à `roue-chat.html`. Vérifié : le script démarre, répond (« Ajoute Océane. ») et libère la mémoire GPU à l'arrêt (0 Mo).

#### Installation (poste neuf)
1. `gh release download b5454 -R ggml-org/whisper.cpp -p whisper-bin-win-cuda-12.4.0-x64.zip`, décompresser dans `~/tools/whisper-cpp` (le dossier `Release` contient `whisper-server.exe` et les DLL CUDA 12).
2. Télécharger `ggml-large-v3-turbo-q5_0.bin` depuis `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/` dans `~/tools/whisper-modeles`.
Pilote NVIDIA compatible CUDA 12 (ici 617.42, CUDA 13.4 : accepté).
