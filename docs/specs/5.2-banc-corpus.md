# Story 5.2 — Banc d'essai du corpus (V1.1)

Corpus et lecture des scores : `docs/v1.1/README.md`. Code dans `src/banc/`, jamais importé par `src/main.ts`. Lancement : `scripts/banc-chat.mjs` charge `src/banc/cli.ts` par le serveur de Vite (les imports du dépôt n'ont pas d'extension, ce qui exclut `node --experimental-strip-types`) ; aucune dépendance ajoutée.

## Critères d'acceptation
- C1. `npm run banc:chat -- --moteur <nom> [--lot dev|test] [--modele m] [--url u]` : `dev` par défaut ; `test` seulement avec `--lot test` explicite ; moteur obligatoire, moteur inconnu ou à venir refusé avec un message (code 2).
- C2. Chaque ligne du lot passe par `decider` (cascade 5.1) avec les fabriques du moteur ; `--modele`/`--url` deviennent `modele`/`urlOllama`. Aucun appel réseau par défaut.
- C3. Comparateur (`comparateur.ts`) : même action, mêmes paramètres (noms exacts, couleur sans casse, params absent = `{}`, paramètre en trop refusé), étapes dans l'ordre, `refuser` sans comparer le code, `clarifier` selon la règle des candidats (1 au moins, 2 dans `homonymes`, présents dans `etat.noms`), confirmation par `confirmationRequise` de la décision obtenue.
- C4. Registre (`moteurs.ts`) : `refuse-tout` ; emplacements documentés `regles` (5.3), `slm` (5.6, branché en 5.7), `decision` (5.10). `--corpus <fichier>` (5.7) lit un export de la fenêtre d'inspection.
- C5. Sortie console : score global, plancher « refuse tout », latence médiane et p95, score par action (une ligne à plusieurs étapes compte pour chaque action distincte) et par catégorie du lot lancé. Détail et traces de cascade dans `.banc/<moteur>-<lot>.json` (ignoré par git).
- C6. `refuse-tout` donne le plancher de `verifier_corpus.py` : dev 26/96, test 32/126 (test automatisé).

## Décisions
- Le moteur factice emprunte le nom d'étage `regles` (`NomEtage` n'est pas modifié).
- Les noms sont comparés exactement : un moteur qui rend « zoe » pour « Zoé » échoue, même si `planifier` le résoudrait.
- `clarifier` : au moins 1 candidat attendu (2 dans `homonymes`) parmi ceux obtenus ; les candidats en trop sont tolérés.
- Le score principal juge la décision après `planifier` (état du domaine construit depuis le corpus) ; le score sur la décision brute est un indicateur secondaire (`globalBrut`, `okBrut`).
- Par action : rappel, émissions, émissions à tort, précision (console et JSON).

## Reports
- Aucun score par lot croisé (dev + test dans une même exécution) : volontaire.
