# Story 5.10 — Étage décision (V1.1), étape A

Cadrage : `docs/v1.1-chat-slm.md` (« Moteur de décision »). Code : `src/chat/decision.ts` (tests `decision.test.ts`), jamais importé par `src/main.ts`. L'étape A se fait sans GPU, sur serveur simulé ; l'étape B vérifie le contrat par un appel réel.

## Contrat supposé, à vérifier par un appel réel
`POST {url}/v1/systemone`, servi par Ollama (port 11434) ou par llama-server selon le modèle. Rien de ceci n'a été vu dans une réponse réelle :
- requête `{ model, messages, questions: [{ id, type, question, options? }] }`, 1 à 256 questions ;
- réponse `{ answers: [{ id, type, … }], usage }` ;
- `noul` : `probability` (0 à 1), seuil naturel à 0,5 ;
- `choice` : `probabilities`, objet `{ option: p }` ou liste `[{ option | label, probability }]` (forme exacte inconnue, les deux sont lues) ;
- `score` : non utilisé.

## Critères d'acceptation
- C1. `AdaptateurDecision` (chemin, `requete`, `reponses`) isole tout le contrat ; `ADAPTATEUR_SYSTEMONE` est l'implémentation supposée. Le contrat réel ne remplacera que lui. `creerEtageDecision(options, adaptateur?)`.
- C2. Étage inactif (`null`, aucun appel) sans `modeleDecision` (nouveau champ d'`OptionsEtages`, avec `urlDecision`, à défaut `urlOllama`, et `seuilDecision`, 0,5 par défaut).
- C3. Question `outil` : `choice` parmi les outils exécutables plus `aucun`. `aucun` : passe la main (`aucun-outil`). Meilleure option sous le seuil : `incertain`.
- C4. Paramètres libres jamais demandés : un paramètre requis de type chaîne sans énumération (nouveau nom, couleur, texte) donne `parametre-libre` ; booléen ou énuméré, `parametre-non-gere`. Dans les deux cas un seul appel a été fait.
- C5. Outil visant une personne : deuxième appel, `choice` `nom` sur les candidats (noms cités dans la commande, sinon tous, sans doublon de forme, au plus 50) et `noul` `ambigu`. `ambigu` au seuil ou au-dessus : décision `clarifier` (3 candidats les plus probables). Nom sous le seuil : `incertain`. Les homonymes sont laissés à `planifier` (clarifier).
- C6. `lancer` et les outils sans paramètre : un seul appel, aucune question sur un gagnant, `params: {}`.
- C7. Noms en données : JSON entre `<<<DONNEES>>>` et `<<<FIN_DONNEES>>>`, `<` et `>` échappés comme dans `slm.ts`.
- C8. Robustesse : délai (`delaiMs`, un seul pour toute la commande, `Promise.race`), annulation, 403 et 404 et connexion refusée (`indisponible`, `etat()` et `raisonIndisponible()`), 500 (`erreur-http`), JSON invalide, réponse mal formée ou probabilité hors de [0, 1] (`reponse-invalide`) : passes de main.
- C9. Trace : `derniereTrace()` (messages, questions et réponse brute de chaque appel avec sa durée, probabilités lues, rejet, durée totale) ; `ResultatEtage.trace` = corps envoyés en entrée, dernière réponse brute en sortie ; `confiance` = plus petite probabilité retenue.
- C10. Enregistré entre `regles` (5.3) et `slm` dans `ETAGES_ENREGISTRES`.
