# Story 5.10 — Étage décision (V1.1), étape A

Cadrage : `docs/v1.1-chat-slm.md` (« Moteur de décision »). Code : `src/chat/decision.ts` (tests `decision.test.ts`), jamais importé par `src/main.ts`. L'étape A se fait sans GPU, sur serveur simulé ; l'étape B vérifie le contrat par un appel réel.

## Contrat constaté (étape B, 2026-11-04)
Appel réel de `POST /v1/systemone` sur Ollama 0.40.4 (`tev1:0.8b`, capacité `decision`) et sur llama-server b12100 (Julia-1 et Laya en Q8_0, `ggml-org/Julia-1-GGUF` et `ggml-org/Laya-GGUF`). Même contrat des deux côtés ; les hypothèses de l'étape A (liste de messages, liste de questions, `probability`) étaient fausses.
- Requête : `{ model, state, questions: { <id>: { type, instructions, criteria? } } }`. `model` obligatoire pour Ollama (`model is required`), ignoré par llama-server. `state` : chaîne (un objet passe aussi) ; `messages` n'est pas lu. `questions` : objet de 1 à 64 champs (`questions must contain 1–64 fields`), pas une liste. `type` : `choice`, `score` ou `noul`. `instructions` obligatoire. `choice` : `criteria`, objet non vide `{ option: description }` ; `score` : `criteria`, liste de 2 à 10 niveaux.
- Réponse 200 : `{ model, answers: { <id>: … }, usage: { input_tokens, output_tokens: 0 } }`.
  - `choice` : `{ type, choice, probabilities: { option: p }, confidence }`. `probabilities` somme 1 ; `confidence` est un indice propre au serveur (non utilisé).
  - `noul` : `{ type, noul }` (et non `probability`).
  - `score` : `{ type, score, legend: { "0": …, "1": … }, probabilities, confidence }` ; non utilisé.
- Erreurs : HTTP 400, `{ "error": "…" }` (par ex. `"state" must be provided`, `questions.x: "criteria" must be a non-empty object`, `questions.a: "type" must be one of: choice, score, noul`). L'étage les rend en `erreur-http`.
- `ADAPTATEUR_SYSTEMONE` corrigé : `state` = consignes, état et commande concaténés ; `criteria` = `{ option: option }` (pas de description par outil pour l'instant) ; lecture de `answers` par id, de `probabilities` (objet seulement) et de `noul`. Les probabilités sont bien normalisées (somme 1) ; le rejet hors de 1 ± 0,05 reste.

## Critères d'acceptation
- C1. `AdaptateurDecision` (chemin, `requete`, `reponses`) isole tout le contrat ; `ADAPTATEUR_SYSTEMONE` est l'implémentation du contrat constaté ; un autre serveur ne remplacera que lui. `creerEtageDecision(options, adaptateur?)`.
- C2. Étage inactif (`null`, aucun appel) sans `modeleDecision` (nouveau champ d'`OptionsEtages`, avec `urlDecision`, à défaut `urlOllama`, et `seuilDecision`, 0,6 par défaut).
- C3. Question `outil` : `choice` parmi les outils exécutables plus `aucun`. `aucun` : passe la main (`aucun-outil`). Meilleure option sous le seuil : `incertain`.
- C4. Paramètres libres jamais demandés : un paramètre requis de type chaîne sans énumération (nouveau nom, couleur, texte) donne `parametre-libre` ; booléen ou énuméré, `parametre-non-gere`. Dans les deux cas un seul appel a été fait.
- C5. Outil visant une personne : deuxième appel, `choice` `nom` sur les candidats : les candidats sont les noms de la liste cités EN ENTIER dans la commande (frontières de mot, forme normalisée sans accents ni casse ni ponctuation, sans doublon de forme, sans troncature). Aucun nom cité (liste vide, ou nom absent même proche : « Evan » pour « Eva ») : l’étage passe la main avec `nom-non-cite`, sans interroger le modèle ; la 5.1 rendra `clarifier` ou `nom-absent`. Jamais de choix parmi des noms que l’utilisateur n’a pas cités. Sinon deuxième appel : `choice` `nom` sur les candidats et `noul` `ambigu`. `ambigu` au seuil ou au-dessus : décision `clarifier` (3 candidats les plus probables). Nom sous le seuil : `incertain`. Homonymes : dédoublonnés dans les options ; exigence du contrat : toute décision de la cascade passe par `planifier` avant d’être exécutée, qui rend `clarifier` pour des homonymes.
- C6. `lancer` et les outils sans paramètre : un seul appel, aucune question sur un gagnant, `params: {}`.
- C7. Noms en données : JSON entre `<<<DONNEES>>>` et `<<<FIN_DONNEES>>>`, `<` et `>` échappés par `neutraliser` (partagée avec `slm.ts`), aussi dans `questions[].options` (le nom d’origine est rétabli à la lecture de la réponse).
- C8. Robustesse : délai (`delaiMs`, un seul pour toute la commande, `Promise.race`), annulation, 403 et 404 et connexion refusée (`indisponible`, `etat()` et `raisonIndisponible()`), 500 (`erreur-http`), JSON invalide, réponse mal formée ou probabilité hors de [0, 1] (`reponse-invalide`) : passes de main. Probabilités d’une question `choice` : une option inconnue ou une somme hors de 1 ± `TOLERANCE_SOMME` (0,05) donne `forme-invalide` ; rejet, pas de normalisation (le serveur réel renvoie des probabilités de somme 1).
- C9. Trace : `derniereTrace()` (messages, questions et réponse brute de chaque appel avec sa durée, probabilités lues, rejet, durée totale) ; `ResultatEtage.trace` = corps envoyés en entrée, dernière réponse brute en sortie ; `confiance` = plus petite probabilité retenue.
- C10. Enregistré entre `regles` (5.3) et `slm` dans `ETAGES_ENREGISTRES`.
