# Story 5.6 — Client SLM (V1.1)

Cadrage : `docs/v1.1-chat-slm.md`. Code : `src/chat/slm.ts` (tests `slm.test.ts`), jamais importé par `src/main.ts`.

## Critères d'acceptation
- C1. `creerEtageSlm(options)` : `POST {urlOllama}/api/chat` (défaut `http://localhost:11434`), non streamé, `tools` = `definitionsOllama()` ; `think`, `temperature` (0,1 par défaut) et `delaiMs` (8 s) lus dans `OptionsEtages` ; `fetch` injectable. Inactif (`null`, aucun appel) sans `modele`. Enregistré en dernier dans `ETAGES_ENREGISTRES`.
- C2. Contexte : consignes système, puis un seul message utilisateur : l'état (noms, rotation, `EtatChat.prochainCadeau`, et au plus `MAX_ECHANGES` (3) échanges de `EtatChat.historique`, jamais rejoués en tours de dialogue) en JSON entre `<<<DONNEES>>>` et `<<<FIN_DONNEES>>>`, avec `<` et `>` échappés (`<`, `>`) pour qu'un nom ne ferme pas le bloc, puis `Commande : …`.
- C3. Réponse : `tool_calls` vers `Decision` (un appel : `{action, params}` ; plusieurs : `{actions}`), validés par `validerParametres` et `formeValide`. Sans appel, outil inconnu, paramètres invalides (dont `lancer` avec un gagnant) : passage de main `{ decision: null, raison, trace }`. Aucun champ de confirmation du modèle n'est repris.
- C4. Robustesse : délai (défaut 8 s, `Promise.race`, même si `fetch` ignore le signal) et annulation ; connexion refusée, 403 (`OLLAMA_ORIGINS`), 404 (modèle absent) : passage de main et `etat()` = `indisponible` avec `raisonIndisponible()` ; délai, annulation, 500, JSON invalide : passage de main sans changer l'état (`disponible` n'est posé qu'après une réponse JSON valide). Un seul essai par commande.
- C5. Trace : `derniereTrace()` (messages complets, jetons estimés = ⌈caractères / 4⌉, réponse brute, appels d'outils, rejet, `total_duration`, `eval_count`, durée) ; `ResultatEtage.trace` = messages JSON en entrée, réponse brute en sortie ; `TraceEtage.raison` = code court.
