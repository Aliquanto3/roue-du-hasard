# Story 5.6 — Client SLM (V1.1)

Cadrage : `docs/v1.1-chat-slm.md`. Code : `src/chat/slm.ts` (tests `slm.test.ts`), jamais importé par `src/main.ts`.

## Critères d'acceptation
- C1. `creerEtageSlm(options, reglages?)` : `POST {urlOllama}/api/chat` (défaut `http://localhost:11434`), non streamé, `tools` = `definitionsOllama()`, `think` optionnel, température 0,1 par défaut ; `fetch` injectable. Inactif (`null`, aucun appel) sans `modele`. Enregistré en dernier dans `ETAGES_ENREGISTRES`.
- C2. Contexte : consignes système françaises, au plus `MAX_ECHANGES` (3) derniers échanges, puis un message avec l'état (noms, rotation, prochain cadeau = `cadeaux[0]`) en JSON entre `<<<DONNEES>>>` et `<<<FIN_DONNEES>>>` (un nom n'est jamais une instruction), puis `Commande : …`.
- C3. Réponse : `tool_calls` vers `Decision` (un appel : `{action, params}` ; plusieurs : `{actions}`), validés par `validerParametres` et `formeValide`. Sans appel, outil inconnu, paramètres invalides (dont `lancer` avec un gagnant) : `null`, raison dans la trace. Aucun champ de confirmation du modèle n'est repris.
- C4. Robustesse : délai (défaut 8 s) combiné au signal ; connexion refusée, 403 (`OLLAMA_ORIGINS`), 404 (modèle absent) : `null` et `etat()` = `indisponible` avec `raisonIndisponible()` ; délai, annulation, 500, JSON invalide : `null` sans changer l'état. Un seul essai par commande.
- C5. Trace : `derniereTrace()` (messages complets, jetons estimés = ⌈caractères / 4⌉, réponse brute, appels d'outils, rejet, `total_duration`, `eval_count`, durée) ; `ResultatEtage.trace` = messages JSON en entrée, réponse brute en sortie.

## Reports
- Le panneau (5.5) affiche `TEXTES_CHAT.slmIndisponible` d'après `etat()` ; l'historique réel est branché par `reglages.historique`.
- Aucun appel à un Ollama réel dans les tests (fetch simulé).
